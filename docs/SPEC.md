# smarcivaZIP 仕様書

## 0. 位置づけ

Lhaplus (2000〜2015 / 最終 1.74) の後継。
Lhaplus の「ダブルクリックで即解凍／右クリックで形式を選んで圧縮」という
**操作の単純さだけ**を継承し、実装は 2026 年時点の要求に合わせて全面的に作り直す。

Lhaplus の積み残し課題（本プロジェクトで解決するもの）:

| 課題 | Lhaplus | smarcivaZIP |
|---|---|---|
| RAR5 (RAR 5.0) | 非対応 | 対応（展開のみ） |
| Zstandard / XZ / LZ4 | 非対応 | 対応 |
| ZIP AES 暗号化 | 非対応（ZipCrypto のみ） | 対応 |
| 文字化け | CP932 固定、他国ZIPで破綻 | 自動判定＋手動切替＋プレビュー |
| macOS 製 ZIP の NFD 濁点分解 | 非対応 | NFC 正規化 |
| `__MACOSX` / `._*` / `.DS_Store` | そのまま展開 | 自動除去（既定 ON） |
| Zip Slip / Zip Bomb | 無防備 | 検出してブロック |
| 260 文字超パス | 失敗 | `\?\` で対応 |
| 64bit / ARM64 | 32bit のみ | x64 / arm64 ネイティブ |
| MOTW 継承 | 無し | 継承（既定 ON） |

## 1. 対応フォーマット

`7z.dll` の実装に依存するため、**起動時に DLL からハンドラ一覧を動的列挙**し、
実際に使える形式だけを UI に出す。以下は 7-Zip 25.x を同梱した場合の期待値。

### 展開 (Read)

7z, ZIP, ZIPX, RAR, **RAR5**, TAR, GZ, BZ2, XZ, **ZST**, LZ4(※DLL依存), LZMA,
**LZH / LHA**, CAB, ARJ, Z, CHM, MSI, NSIS, ISO, **DMG / HFS / HFS+**, APFS(※),
WIM, CPIO, RPM, DEB, XAR, SquashFS, CramFS, VHD/VHDX/VMDK/VDI, FAT/NTFS/EXT, UDF, AR

### 圧縮 (Write)

| 表示名 | 実体 | 備考 |
|---|---|---|
| ZIP | zip / Deflate | 既定。互換性最優先 |
| ZIP（パスワード） | zip / Deflate + **AES-256** | |
| 7z | 7z / LZMA2 | 高圧縮 |
| 7z（パスワード） | 7z / LZMA2 + AES-256 + **ヘッダ暗号化** | ファイル名も秘匿 |
| TAR.GZ | tar → gzip | |
| TAR.XZ | tar → xz | |
| TAR.ZST | tar → zstd | DLL が zstd 対応のときのみ表示 |
| 自己解凍 EXE | 7z + SFX モジュール | v2 |

RAR 形式での圧縮は **行わない**（unRAR ライセンス制限。THIRD-PARTY-NOTICES.md 参照）。

## 2. 文字化け対策

### 2.1 ZIP

1. ZIP のセントラルディレクトリを**自前でパース**し、ファイル名の**生バイト列**と
   汎用目的ビットフラグ (bit 11 = EFS/UTF-8) を取得する。
2. 判定順:
   - bit 11 が立っている → UTF-8
   - Info-ZIP Unicode Path Extra Field (0x7075) がある → その UTF-8 名を採用
   - 全バイトが ASCII → 判定不要
   - それ以外 → **統計的コードページ判定**（2.3）
3. 判定したコードページを `ISetProperties` で zip ハンドラの `cp` プロパティに設定し、
   7z.dll に正しくデコードさせる。

### 2.2 統計的コードページ判定

候補: UTF-8 / CP932 (Shift_JIS) / CP936 (GBK) / CP949 (EUC-KR) / CP950 (Big5) /
CP866 (キリル DOS) / CP1252 / CP437

スコアリング:
- UTF-8 として厳密に妥当か（不正シーケンスがあれば即除外）
- 各コードページでデコードした結果に含まれる文字の「もっともらしさ」
  - 日本語: ひらがな・カタカナ・常用漢字・全角記号の比率
  - 中国語: 簡体/繁体の常用漢字の比率
  - 韓国語: ハングル音節の比率
  - 未定義コードポイント・私用領域・制御文字が出たら大幅減点
- ファイル名として典型的な文字（`_ - ( ) [ ] 0-9 .` と拡張子）を加点
- 同点時は CP932 を優先（日本語ユーザー向けの既定）

判定結果はプレビュー画面に表示し、ユーザーがドロップダウンで**手動上書き**できる。
選択は即座にプレビューへ反映される。

### 2.3 macOS 由来アーカイブ

- macOS の Finder が作る ZIP は **UTF-8 NFD**。「ガ」が「カ」+ U+3099 に分解されて
  Windows 上で不自然に見える／検索できない。→ **NFC 正規化**して展開する。
- `__MACOSX/` 配下、`._` で始まる AppleDouble ファイル、`.DS_Store`、`.fseventsd`、
  `.Spotlight-V100`、`.Trashes` を既定で除外する。
- 除外するとルート直下が単一フォルダになる場合、「フォルダにまとめる」判定は
  **除外後のエントリ構成**で行う。
- DMG は HFS+ / 一部 APFS を 7z.dll 経由で展開。HFS+ の圧縮属性
  (`com.apple.decmpfs`) が付いたファイルは 7z.dll が展開時に解決する。

### 2.4 その他

- LZH / LHA: ヘッダに文字コード情報がないため CP932 固定（判定 UI からの上書きは可）
- RAR: RAR3 は OEM/Unicode 両方の名前を持つ。RAR5 は常に UTF-8
- 7z: 常に UTF-16

## 3. 安全性

| 脅威 | 対策 |
|---|---|
| Zip Slip (`../` 脱出、絶対パス、ドライブレター) | 展開先を正規化し、出力ルート配下に収まらないエントリは**拒否** |
| シンボリックリンク / ハードリンク経由の脱出 | 既定でリンクを展開しない（設定で許可可） |
| Zip Bomb | 展開後サイズ / 圧縮後サイズ比、総展開サイズ、エントリ数の上限で検出し確認ダイアログ |
| Windows 予約名 (CON, PRN, AUX, NUL, COM1-9, LPT1-9) | 末尾に `_` を付けてリネーム |
| 代替データストリーム注入 (`name:stream`) | `:` をサニタイズ |
| 末尾ドット・空白 | 除去 |
| 260 文字超 | `\?\` プレフィックスで長いパスを使用 |
| MOTW | 元アーカイブの Zone.Identifier を展開後ファイルへ伝播（既定 ON） |
| 大文字小文字違いの衝突 | 上書きせず `(2)` を付与 |

## 4. UI / UX

### 4.1 解凍（ダブルクリック）

1. 関連付けたアーカイブをダブルクリック → `SmarcivaZip.exe <path>` 起動
2. 文字化けの可能性を検出した場合のみ**プレビューダイアログ**を出す
   （純 ASCII / UTF-8 確定なら出さずにそのまま解凍＝Lhaplus と同じ体感）
3. 進捗ダイアログ（ファイル名 / %）を表示、キャンセル可
4. 完了後、設定に従ってフォルダを開く

出力先の既定:
- アーカイブと同じフォルダ
- ルート直下のエントリが 1 個（フォルダ）→ そのまま展開
- ルート直下が複数 → `アーカイブ名` フォルダを作って展開（tar bomb 防止）

### 4.2 圧縮（右クリック）

エクスプローラの右クリックメニューに `smarcivaZIP` サブメニューを出す。

```
smarcivaZIP  ▸  ZIP に圧縮
                ZIP に圧縮（パスワード）
                7z に圧縮
                7z に圧縮（パスワード）
                TAR.GZ に圧縮
                ────────────
                ここに解凍
                フォルダを作って解凍
                文字コードを選んで解凍…
                ────────────
                設定…
```

どの圧縮形式をここに並べるかは設定画面で選ぶ（Lhaplus の
「[圧縮] のサブメニュー項目」に相当）。並び順も設定した順のまま反映する。
全形式を出すとメニューが長くなりすぎるため、既定は ZIP / ZIP(パスワード) /
7z / 7z(パスワード) / TAR.GZ の 5 つ。

解凍系の項目には `AppliesTo` を付け、関連付けの対象にしている拡張子のときだけ表示する。
フォルダを右クリックしたときは圧縮系だけを出す。

### 4.3 設定

単一ウィンドウ、タブ 5 枚。常駐なし。

タブの順番は **設定 / 解凍 / 圧縮 / 文字コード / 情報**。

先頭の「設定」は関連付けと右クリックメニューの登録を行う画面で、
ここを通らないとエクスプローラーからは何も使えないため最初に置く。
文字コードは、困ったときだけ開けばよい内容なので後ろに回す。

設定は `%APPDATA%\smarcivaZIP\settings.json`。

関連付けは Lhaplus と同じくチェックボックスの一覧で選ぶ。

- 一覧に並べる拡張子（`ExtensionChoices`）と、チェックが入っている拡張子
  （`AssociatedExtensions`）を別々に持つ。こうしないと、チェックを外した拡張子が
  一覧から消えてしまい、戻せなくなる
- 「追加」で任意の拡張子を足せる。「削除」は選択中の行を一覧から消す
- 「7z.dll が扱える拡張子をすべて追加」で、読み込んでいる DLL の対応拡張子を
  一覧に流し込める（チェックは入れない。iso や vhd まで関連付けられると困るため）
- 登録時は、一覧にあってチェックが外れている拡張子から関連付けを**解除**する。
  これをやらないと、一度入れたチェックを外しても関連付けが残り続ける

## 4.4 表示言語

20 言語。既定は Windows の表示言語に追従し、未対応の言語は英語に落ちる。
設定画面で固定もできる。切り替えは再起動後に反映される
（XAML のリソース参照はウィンドウ生成時に解決されるため）。

en / zh-Hans / zh-Hant / es / ar / pt / id / fr / ja / ru /
de / ko / tr / it / vi / pl / th / nl / uk / hi

選定は話者数ではなくインターネット利用者数で行った。母語話者だけを見ると
書き言葉としては別言語を使う地域を取りこぼすためである。この 20 言語で約 9 割、
上位 10 言語ほどで約 8 割に届く。それ以降は 1 言語あたりの上積みが急落するので、
地域方言には踏み込まない。

アラビア語は右から左に書くため、`AppLanguage.IsRightToLeft` を見て
`FlowDirection` をウィンドウ全体に適用する。WPF はこのとき HWND に
`WS_EX_LAYOUTRTL` を立てるので、`PrintWindow` で取った画像は左右が反転する。
スクリーンショットで確認するときは反転させて見ること（画面表示自体は正しい）。

タイ語・ヒンディー語・アラビア語は `App.xaml` の `UiFont` のフォールバックで
Nirmala UI / Leelawadee UI / Segoe UI に落として字形を得る。
いずれも Windows 10 以降に標準で入っており、追加導入は要らない。

文字列は `SmarcivaZip.Core/Resources/Strings.resx`（英語・中立）と
`Strings.<言語コード>.resx` に置き、`ResourceManager` を直接引く。
Visual Studio が生成する `*.Designer.cs` は使わない。
あれはデザイン時ツールの生成物で、`dotnet build` だけの CI では作られず、
生成物をコミットすると resx とずれる余地が残るためである。
キーの実在はテストで担保する。

表示言語は文字コード判定の優先言語にも反映される。
以前は CP932 固定だったため、韓国語や中国語の利用者が自分の言語の書庫を開いても
日本語が優先されるという不具合があった。

翻訳を増やすときは resx を足し、`AppLanguage.Available` に登録する。
一覧に載せるのは訳が揃った言語だけとする。

## 4.4.1 複数選択のまとめ方

レジストリだけで作った右クリックメニューは、複数のファイルを選んで実行すると
**ファイルごとに別プロセス**として起動される。放置すると 10 個選んで圧縮したときに
書庫が 10 個できる。

最初に起動したプロセスが名前付きセマフォを取って先頭になり、名前付きパイプで
待ち受ける。後続のプロセスは自分のパスを送って静かに終了する。
COM のシェル拡張なら一度の呼び出しで全部受け取れるが、
それはエクスプローラーに自前の DLL を読み込ませることを意味するので採らない。

締め切りは **1 件届くたびに 600 ms 延びる**。到着間隔が 600 ms 未満なら何個でも拾える。

実測（発行版 exe、この開発機）:

| 選択数 | 到着のばらつき | 結果 |
|---|---|---|
| 10 | 約 130 ms | 書庫 1 個 |
| 30 | — | 書庫 1 個 |
| 60 | 約 2,447 ms | 書庫 1 個 |

60 件でも到着が 2.4 秒に散らばったが、間隔そのものは 600 ms を超えないため
すべて 1 つにまとまった。締め切りを固定にしていたら破綻していた。

排他には Mutex ではなく **Semaphore** を使う。Mutex は取得したスレッドでしか
解放できず、ここは `await` を挟むため、同期コンテキストの無い環境では
別スレッドに戻って解放時に落ちる。WPF の UI スレッドからは元のスレッドに戻るので
表面化しないが、依存してよい性質ではない。

先頭プロセスが異常終了した場合、セマフォは解放されないが、ハンドルが全部閉じれば
カーネルオブジェクトごと消えるので次の操作は新品から始まる。
その間に来た呼び出しはパイプに繋げず、それぞれ単独で処理する
（書庫が分かれるだけで、失敗はしない）。

## 4.5 アイコンと ProgID

`DefaultIcon` は ProgID 単位でしか設定できないため、形式ごとにアイコンを変えるには
ProgID も分ける必要がある。分類は `ArchiveFileType` に定義する。

| ProgID | アイコン | 拡張子 |
|---|---|---|
| `smarcivaZIP.Zip` | zip.ico | zip, zipx, jar |
| `smarcivaZIP.SevenZip` | 7z.ico | 7z |
| `smarcivaZIP.Rar` | rar.ico | rar, r00 |
| `smarcivaZIP.Tar` | tar.ico | tar, tgz, tbz, tbz2, txz, tzst, taz |
| `smarcivaZIP.Compressed` | gz.ico | gz, bz2, xz, zst, lzma, lz4, z |
| `smarcivaZIP.Lzh` | lzh.ico | lzh, lha |
| `smarcivaZIP.Archive` | archive.ico | 上記以外すべて（cab, arj, iso ほか） |

形式ごとに 1 種類ずつ用意するのではなく、まとめられるものはまとめる。
`.tgz` と `.tar.gz` に別のアイコンを与えても利用者には区別が付かず、
一覧に並んだときに色が増えすぎて読み取りにくくなるだけである。

アプリ本体と書庫は**形**で分ける。同じ絵だと、同じフォルダに並んだときに
どれが実行ファイルか分からない。形式の区別は**色**で行う。
エクスプローラーの詳細表示は 16px で、その大きさでは文字が読めないため。

`.ico` は実行ファイルに埋め込まず、隣の `Icons` フォルダに置く。
exe に複数のアイコンを入れるには Win32 リソースを自前で用意する必要があり、
.NET SDK からは素直に扱えない。外に出しておけば利用者が差し替えられる利点もある。

登録時は、その拡張子に割り当たっている古い ProgID を `OpenWithProgids` から
取り除いてから新しいものを書く。残すと「プログラムから開く」に
smarcivaZIP が二重に並ぶ。

## 5. アーキテクチャ

```
SmarcivaZip.App (WPF, net9.0-windows)
  └─ SmarcivaZip.Core (net9.0-windows)
       ├─ SevenZip/      7z.dll の P/Invoke + COM インターフェイス
       ├─ Encodings/     コードページ判定・ZIP セントラルディレクトリ解析・NFC 正規化
       ├─ Safety/        パスのサニタイズ・Zip Bomb 検出
       ├─ Extraction/    展開ジョブ
       ├─ Compression/   圧縮ジョブ
       ├─ Shell/         関連付け・右クリックメニューのレジストリ登録
       └─ Settings/      設定の読み書き
```

`7z.dll` は `LoadLibrary` + `CreateObject` で動的に読み込む。
COM 登録は不要（レジストリフリー）。
